在 macOS 上部署 DeepSeek Harness 并用 launchctl 托管进程

Published: 六 22 八月 2026
By DJ.shao

In 人工智能.

tags: blog ai agent deepseek macos launchctl

DeepSeek Harness 是 DeepSeek 开源的一款 Agent 运行时（命令行工具叫 dsh），提供会话管理、工具调用、工作区沙箱和 Web UI。它本身不跑模型推理，而是调用 DeepSeek API（如 deepseek-v4-flash），所以一台普通 Mac 就能把它跑起来。

本文记录在 macOS 上从零部署，并用 launchctl 把它变成开机自启、崩溃自动重启的常驻服务。

环境准备

Harness 基于 Node.js，要求 Node.js 22.19+ 或 24+。用 Homebrew 安装：

brew install node@22

验证版本：

node --version   # v22.x 或 v24.x
npm --version

手动跑起来

先申请一个 DeepSeek API Key，然后直接启动：

export DEEPSEEK_API_KEY="sk-xxxxxxxx"
npx @deepseek-ai/dsh web

看到启动成功后，浏览器打开 http://127.0.0.1:3080，接受开发者预览声明，在 Settings → Models 里填入 API Key 并选择模型即可开始使用。

注意：DEEPSEEK_API_KEY 只在当前终端会话生效，关掉终端服务就停了——这正是下一步要用 launchctl 的原因。

编写 LaunchAgent 配置

macOS 推荐用 LaunchAgent（用户级服务）托管这类常驻进程。创建 ~/Library/LaunchAgents/com.deepseek.dsh.plist：

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
 "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.deepseek.dsh</string>

    <key>ProgramArguments</key>
    <array>
        <!-- 改成 which npx 的实际路径 -->
        <string>/opt/homebrew/bin/npx</string>
        <string>@deepseek-ai/dsh</string>
        <string>web</string>
        <string>--port</string>
        <string>3080</string>
    </array>

    <!-- 环境变量：API Key 和 PATH -->
    <key>EnvironmentVariables</key>
    <dict>
        <key>DEEPSEEK_API_KEY</key>
        <string>sk-xxxxxxxx</string>
        <key>PATH</key>
        <string>/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin</string>
    </dict>

    <key>WorkingDirectory</key>
    <string>/Users/shaodj/dsh-workspaces/sandbox-project</string>

    <!-- 登录时自动启动 -->
    <key>RunAtLoad</key>
    <true/>

    <!-- 进程退出后自动拉起（无论正常还是异常退出） -->
    <key>KeepAlive</key>
    <true/>

    <!-- 日志输出 -->
    <key>StandardOutPath</key>
    <string>/tmp/dsh.log</string>
    <key>StandardErrorPath</key>
    <string>/tmp/dsh.err.log</string>
</dict>
</plist>

几个关键点：

  • ProgramArguments 必须写绝对路径，launchd 不继承 shell 的 PATH；先用 which npx 查一下自己的路径。
  • WorkingDirectory 指向 Agent 的工作区目录，建议单独建一个测试目录，不要直接用家目录。
  • KeepAlive 设为 true 后进程挂了会被自动重启。

加载与管理服务

macOS 新版推荐 bootstrap/bootout 语法：

# 加载并立即启动
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.deepseek.dsh.plist

# 查看状态
launchctl print gui/$(id -u)/com.deepseek.dsh | grep state

# 重启服务
launchctl kickstart -k gui/$(id -u)/com.deepseek.dsh

# 卸载服务
launchctl bootout gui/$(id -u)/com.deepseek.dsh

老式的 load/unload 也仍然可用：

launchctl load   ~/Library/LaunchAgents/com.deepseek.dsh.plist
launchctl unload ~/Library/LaunchAgents/com.deepseek.dsh.plist

修改 plist 后需要先 bootout 再 bootstrap 重新加载才会生效。

验证

curl -sI http://127.0.0.1:3080 | head -1
# HTTP/1.1 200 OK

tail -f /tmp/dsh.log

再测一下崩溃自愈：kill 掉 dsh 进程后几秒内 launchctl print 会看到它被重新拉起，这正是 KeepAlive 在起作用。

小结

整个过程三步：装 Node.js → 写 plist → bootstrap 加载。之后 Harness 就像系统服务一样常驻后台，重启 Mac 也会自动恢复，配合浏览器随时可用。
